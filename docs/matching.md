# Локальное сопоставление товаров

Модуль реализует часть описанного пользователем процесса: поиск товара 1С по такому же артикулу или штрихкоду. Он работает только с переданными данными и выдаёт предложения. Он не подключается к 1С, не нажимает кнопки, не сохраняет связи и не создаёт документы.

## Формат данных

Пример находится в `examples/matching.json`. Все коды и идентификаторы передаются строками, включая числовые на вид артикулы и штрихкоды.

Входной объект содержит ровно два поля:

- `catalog`: снимок каталога для выбранных организации (`organization_id`) и кабинета (`cabinet_id`), а также список `products`.
- `lines`: непустой список строк заказов для поиска соответствий.

В товаре обязательны `product_id` и `name`. Необязательные поля — `article`, список `barcodes` и `variant_id` для характеристики товара. Пара `product_id` и `variant_id` должна быть уникальна в снимке. Отдельные характеристики могут иметь одинаковый артикул.

В строке заказа обязательны `organization_id`, `cabinet_id`, `order_id` и `line_id`. Поля `article` и `barcode` необязательны; при отсутствии обоих строка попадёт на ручной разбор. Неизвестное значение задаётся отсутствующим полем или `null`, а не пустой строкой. Повтор одной строки одного заказа в одном кабинете отклоняется.

Этот формат ещё не связан с реальной схемой данных 1С. Будущий адаптер должен получать значения из правильных полей и обеспечивать достоверность меток организации и кабинета. Сейчас модуль проверяет совпадение переданных меток, но не проверяет их по внешней системе.

## Правила

1. Организация и кабинет строки должны совпадать с контекстом каталога.
2. Артикул сравнивается только с артикулом, штрихкод — со списком штрихкодов. Сравнение точное: начальные нули, регистр и пробелы не изменяются. Поиск по названию не используется.
3. Если указан один код, выбирается единственный товар или характеристика с этим кодом.
4. Если указаны артикул и штрихкод, оба должны быть найдены. Единственное общее соответствие выбирается; один код может уточнить несколько совпадений по другому.
5. Если один из двух переданных кодов не найден, совпадение только по оставшемуся коду не принимается автоматически. Если коды указывают на разные товары, результат тоже требует разбора.
6. Ни отсутствие совпадений, ни несколько совпадений не приводят к автоматическому созданию номенклатуры или выбору первого товара.

При наличии сохранённого соответствия в 1С будущая интеграция должна использовать его и проверять состояние заказа. Этот модуль не хранит соответствия и не заменяет уже сохранённые связи.

## Результат

Статус `matched` означает одно точное предложение. Статус `needs_review` означает, что модуль не выбрал товар. В результатах указываются причина, исходная строка заказа, кандидаты и, при успехе, выбранный товар с характеристикой. Совпадение в локальном файле ещё не означает, что связь записана в 1С или заказ повторно загружен.

| Причина | Значение |
| --- | --- |
| `exact_match` | Найдено единственное точное соответствие |
| `scope_mismatch` | Организация или кабинет не совпадают |
| `missing_identifier` | Нет артикула и штрихкода |
| `not_found` | Хотя бы один переданный код не найден |
| `conflicting_identifiers` | Артикул и штрихкод указывают на разные товары |
| `ambiguous_match` | Осталось несколько кандидатов |

Код завершения команды: `0` — все строки сопоставлены, `2` — есть строки для разбора, `1` — входной файл некорректен или недоступен. При ошибке входных данных выводится сообщение в stderr, а частичные предложения не публикуются.

## Следующий шаг интеграции

Локальный чат «Определить конфигурацию 1С» подтвердил управление уже открытым RDP-сеансом на ноутбуке. По его отчёту используется УТ 11.4.6.188 на платформе 8.3.27.1688, установлены расширения для маркетплейсов. Управление из облачной задачи по-прежнему не установлено; дальнейший осмотр проводится в локальной Windows-задаче.

Далее нужно определить точные расширения и посмотреть используемое окно сопоставления: поля артикула и штрихкода, выбор номенклатуры/характеристики и сохранение связи. По этим данным можно выбрать поддерживаемый программный интерфейс или реализацию через интерфейс Windows. Затем требуется проверить сохранение связи и повторную загрузку заказа на реальной системе. Детали продолжения — в [local-continuation.md](local-continuation.md).
