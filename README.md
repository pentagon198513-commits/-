# Помощник для поставок из 1С

Проект автоматизации обработки заказов Wildberries по схеме FBS, подготовки поставок и этикеток для трёх юрлиц: Белименко Елена, Белименко Сергей и Нота. Пользователь работает с 1С через удалённый рабочий стол Windows. Поставки и этикетки оформляются в 1С.

Требования и вопросы для подключения описаны в [описании процесса](docs/workflow.md).

Описанный пользователем процесс для пустого поля товара: синхронизация товаров по кабинету WB → сопоставление артикула из «сборки» с номенклатурой 1С → сохранение → повторная загрузка заказов.

Реализован первый локальный компонент: точное сопоставление товаров по артикулу и штрихкоду. Он возвращает предложение соответствия или причину, по которой нужен ручной разбор. Входной JSON — внутренний формат проекта с демонстрационными данными, а не готовая выгрузка из 1С.

В локальной Windows-задаче подтверждено управление уже открытым удалённым рабочим столом и определена конфигурация: **«Управление торговлей, редакция 11», 11.4.6.188**, платформа **8.3.27.1688**. Установлены расширения для маркетплейсов; их точные названия и интерфейсы ещё нужно изучить.

Подключение программного модуля к 1С, чтение реальных заказов, сохранение соответствий, создание поставок, печать и отправка документов пока не реализованы. План продолжения в Windows — в [инструкции для локальной задачи](docs/local-continuation.md).

## Локальный запуск

Нужен Python 3.10 или новее. Сторонних зависимостей нет. Команды выполняются из корня репозитория (в текущей облачной среде это `/workspace/-`).

```sh
python -m supply_assistant examples/matching.json
python -m unittest discover -s tests -v
```

Демонстрация содержит четыре строки: одно точное совпадение и три случая для разбора — неизвестный артикул, неоднозначный артикул и другой кабинет. Ожидаемый код завершения демонстрации — **2**, поскольку есть строки для разбора. Код **0** означает, что все строки сопоставлены; **1** — некорректные входные данные. Результат выводится в JSON; исходный файл не изменяется.

Описание формата и правил — в [документации модуля](docs/matching.md).

Пароли, ключи доступа и данные заказов не следует добавлять в репозиторий. Способ безопасной передачи доступа будет определён после выбора подключения.
